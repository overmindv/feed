# Карантин событий Feed

Накатите миграцию `000006` перед запуском новой версии Feed. Битый
конверт попадет в `feed_event_quarantine`. Повтор доставки того же
topic/partition/offset не создаст новую запись. При отказе БД Parker
повторит текущую запись и остановит подписчика, если попытки исчерпаны.
После рестарта группа продолжит с неподтвержденного offset.

Для алертов подключите `deploy/alerts.yml` к Prometheus, который собирает
`/metrics` Feed. `FeedEventQuarantinePending` срабатывает, когда самой
старой открытой записи больше пяти минут. Метрика равна нулю, если открытых
записей нет, и `NaN`, если запрос к журналу завершился ошибкой.

## Повтор

1. Найдите запись по topic/partition/offset из лога или посмотрите последние
   открытые записи:

   ```sql
   SELECT topic, partition, record_offset, reason, payload_size, rejected_at
   FROM feed_event_quarantine
   WHERE replayed_at IS NULL
   ORDER BY rejected_at
   LIMIT 50;
   ```

2. Возьмите исходный конверт у владельца события или прочитайте одну запись
   Kafka по этим координатам отдельным клиентом без коммита. Не сбрасывайте
   offset группы Feed. Если Kafka уже удалила запись и восстановить данные
   из исходного сервиса нельзя, повтор недоступен.
3. Исправьте конверт, сохранив идентификаторы события и сущности, время и
   версию. Не меняйте тип бизнес-события. Не выкладывайте тело в тикет или
   лог. Передайте его через stdin:

   ```sh
   feed replay -topic task.activity.v1 -partition 0 -offset 123 < corrected.json
   ```

Команда использует `DATABASE_URL` с правом записи в БД Feed. Для аудита
используйте отдельную учетную запись оператора: журнал сохраняет
`session_user` и время повтора. Веб-ручки для повтора нет. Успешный вызов
с уже закрытой записью ничего не меняет. Ошибка валидации или записи
оставляет ее открытой.

Если в исходной записи есть подходящий идентификатор, Feed проверяет его
хеш при повторе. Сначала берется UUID события, при его отсутствии UUID
сущности. Если оба недоступны, вручную сверьте источник и координаты
сообщения и только потом добавьте `-allow-unverified`. Этот флаг не
отключает проверку сохраненного идентификатора.

Координаты уникальны, пока топик не пересоздается с тем же именем. При
переносе на новый кластер с повторным использованием offset используйте
другое имя топика с настройкой Feed либо отдельную БД Feed.
