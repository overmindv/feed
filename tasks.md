# План задач: feed

Дата анализа: **31 октября 2026**. Локальный HEAD: `b16e629`; анализ также учитывает рабочее дерево на 2026-10-31.

## Текущее состояние

Есть read model каталога и задач, дедупликация, токен gateway и limit/offset с нормализацией в repository. created-события каталога попадают в ленту без проверки active; удаление/скрытие не убирает старую запись. Ошибки разбора логируются и пропускаются.

Проверенные опорные файлы: `internal/consumer/events.go`, `internal/consumer/consumer.go`, `internal/repository/postgres.go`, `internal/httpapi/handler.go`.

## Правила выполнения

- Оценка по договорённости: **1 SP ≈ 1 рабочий день; 2 SP ≈ 2 рабочих дня одного разработчика**, включая проверку и review. Это предварительная оценка, не гарантия календарного срока.
- Сначала реализовать весь описанный в карточке функциональный срез, затем написать/обновить тесты последним шагом. Без TDD; общий e2e — после интеграции. Уже существующие проверки не выключать.
- Статус всех карточек: **запланировано**, код по этому backlog ещё не изменён. Наличие исходников и тестов не означает подтверждённую работоспособность.
- Обязательные зависимости указаны явно; рабочая очередь и расчёт срока — в [общем плане](../tasks.md). F0–F4 — технические этапы, а PILOT/PROD/LATER — границы выпуска.
- При смене контракта: согласовать производителя и потребителей, сгенерировать код, обеспечить совместимый rollout. Миграции только append-only; секреты/hidden tests/исходники решений в обычные логи не писать.
- Задачу больше двух дней после уточнения делить на отдельно принимаемые части, сохраняя ID родителя как ссылку. Не скрывать дополнительный объём внутри пункта «и всё остальное».

Всего: **5 задач / 7 SP**; обязательный срез: **1 задач / 2 SP**.

## [feed] Remove unpublished resources from the feed

- **ID:** FED-01
- **Оценка:** 2 SP (2 рабочих дня)
- **Этап:** F1 — надёжная основа; **контур:** PILOT — обязательный срез.
- **Приоритет:** P0 — блокер корректности/безопасности.
- **Зависит от:** [ENT-03](../entities/tasks.md#ent-03).
- **Где менять:** `internal/consumer/events.go`, `internal/repository/postgres.go`.
- **Готово, когда:** Черновики и скрытые ресурсы не видны в общей ленте.

**Шаги:**

1. Фильтровать created по published/active, а не только типу события.
2. Обрабатывать hide/archive/delete через tombstone и удаление доступности старой карточки.
3. Учитывать aggregate_version, чтобы поздняя публикация не воскресила скрытый объект.
4. **Проверка после готовности функционала:** publish→hide→old publish, direct list и duplicate.
